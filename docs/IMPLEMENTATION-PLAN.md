モック: `repos/mock/mock_new/index.html`

**実装するのは入れ物ではなく、中に並んでいる各画面だけ。**

## 2. 作り方の方針

| 項目 | 決めごと |
|---|---|
| フレームワーク | **Next.js（App Router）・JavaScript**（リポジトリが .mjs なので TS にしない） |
| 起動 | `npm run dev` → `next dev -p 3030` |
| 置き場所 | リポジトリ直下に `app/`。既存の `scripts/` `lib/` `supabase/` はそのまま |
| スタイル | モックの見た目に寄せる。**色・フォントは `app/theme.css` の CSS 変数に集約**（藍 `#2B3A52`、背景 `#F6F3EE`、フォント Zen Maru Gothic） |
| 認証 | **Supabase Auth（メール＋パスワード）**。ブラウザは anon キー＋本人のセッションで読む → **RLS がそのまま効く** |
| サーバー処理 | エージェントを動かす処理・`service_role` を使う処理は **Route Handler（サーバー側）だけ**。ファイル1行目に `import 'server-only'`（ルール4） |
| エージェントの共通化 | `scripts/*.mjs` の中身を `lib/agents/recorder.mjs` などの **関数** に切り出し、CLI（scripts）と画面（API）の両方から同じ関数を呼ぶ。**CLI の動きは変えない**（既存の証拠が再現できること） |
| エージェント起動API | **ログイン者の role を確認**してから動かす。外部から叩く用（Cron想定）は **`CRON_SECRET` 必須**（ルール3） |
| 管理者画面のデータ | `quests` `quest_steps` `agent_runs` `tag_mentions` は **ブラウザから見えない設計**（ポリシー無し）。管理者画面ではサーバー側で `role='admin'` を確かめてから `service_role` で読む。**RLS に管理者用ポリシーを足さない**（DESIGN の約束を守る） |

## 4. 画面ごとの仕様（P1）

### 共通
- 左の藍色メニュー: まなぶ（まなびのライブ／知見カード／知識地図）・じぶん（プロフィール／AIからの打診／自己分析）・管理者ビュー（**role=admin のときだけ表示**）
- 右上: 検索（知見カード検索へ）・**ベル**（未回答の打診＋おすすめのライブ）・ログイン中のユーザー
- 管理者メニュー側: ダッシュボード／タグ辞書／企ての一覧／エージェント運用／セキュリティ／メンバーと権限／ユーザー画面へ

### ログイン（`repos/mock/mock-komuro/login.dc.html` を参考）
- メール＋パスワード。デモ用に **架空社員のアカウントを選べるボタン** を置いてよい（ローカル専用。本番では出さない旨をコメント）
- **管理者役の架空社員を1人決める**: `松永 蒼`（人事部＝人材育成担当）を `role='admin'` にする seed を `0010` か別 migration に入れる

### `livehub` まなびのライブ（最初の画面）
- `lives` を「配信中（live）／これから（scheduled）／過去（ended）」で並べる
- 入る／参加予定にする → `live_participants` に insert（RLS: 開催中のライブにだけ参加できる）
- 管理者には **「デモのライブを開く」** ボタン: `docs/demo-transcripts/*.txt` を選ぶと `open-live` の処理を呼ぶ（サーバー側）

### `live` ライブ画面
- 参加者（スピーカー／リスナー）・場づくりエージェントの「最初の一言」（`messages.is_agent=true`）・チャット
- コメント送信 → `messages` insert（F5 のポリシーで守られる）
- 「このライブから生まれるもの」: **生まれたタグごとに知見カードをまとめて表示**
- 管理者に **「ライブを終える」** ボタン → `lives.status='ended'` → タグ付けエージェントを起動（サーバー側）→ 結果を画面に反映
- 音声・「スピーカーになる」は無効表示

### `cards` 知見カード
- 検索（見出し・本文・タグ名）、タグで絞る、カードを選ぶと右に概要
- 「このカードの元になった発言」: **`transcript_segments` の RLS（誘われた人だけ）に任せる**。読めない人には出さない。**本文（body）は要約なので全員に出してよいが、元発言は参加者だけ**（ルール6）
- 「この知見に詳しい人」: 同じタグの `user_tags`（F4 で見えるものだけ）

### `profile` プロフィール
- タブ: 知見タグ／興味タグ／スキルシート／参加したライブ
- 各タグの **公開・非公開の切り替え** → `set_tag_visibility()`（既存の関数）
- 自分の候補タグは「育ちかけ」と表示。自己分析で付いた `source='self'` の非公開タグに **「採用」**（= 公開にする）

### `invite` AIからの打診
- 自分宛の `invitations`（status='sent'）を出す。打診の理由は `quest_steps` の判断理由を **サーバー経由で本人の分だけ** 出す
- 引き受ける／いまは難しい → `respond_invitation()`（既存の関数）
- 引き受けたら、場づくりエージェントの次の一手（日程を決めてライブを予約）が動くこと

### `tags` タグ辞書（管理者）
- 格上げ候補（`proposed`）・候補・正式・弾いた語・禁止 のタブ
- 承認 → `official`、禁止 → `banned`。**ブラウザから管理者のセッションで更新する**（RLS「管理者だけタグを裁ける」がそのまま効く＝証拠になる）
- 格上げ候補には「延べ何回・何人が語ったか」（サーバー経由で `tag_mentions` を数える）

### `quests` 企ての一覧（管理者）
- `quests` をステータス別に。選ぶと `quest_steps` の判断の足あと（skip / wait の理由も）
- 管理者に **「場づくりエージェントを1周動かす」** ボタン（サーバー側で organizer を呼ぶ）

### `admin` ダッシュボード（管理者）
- 数字は **DBから数えられるものだけ**（社員数・ライブ数・カード数・タグの内訳・今月のAI費用＝`agent_runs.cost_usd` 合計）
- 「人が判断する場所」: DESIGN §4 の **4つ**（モックは3つなので合わせる）
