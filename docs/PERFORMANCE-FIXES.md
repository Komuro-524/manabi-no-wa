# 画面遷移停止と動作改善

## 適用方法

1. 起動中の Next.js を停止する。
2. このZIPを**新しいフォルダに展開**する。既存フォルダへの上書きだけでは、削除した `app/(main)/loading.js` が残るため不可。既存の `.env.local` は手元で新フォルダに引き継ぐ。
3. Supabase SQL Editorで未適用のマイグレーションを番号順に実行する。前回版の `0015_agent_safety.sql` が未適用なら先に適用し、今回の `0016_screen_performance.sql` を適用する。0016はインデックスと読み取り用関数の追加で、データ削除やRLSポリシー変更はしない。
4. 新しいフォルダで `npm ci` → `npm run build` → `npm run start`。ブラウザを一度再読み込みする。

AutoRefresh.jsを手で無効化した暫定版や、AdminNavを通常のaタグに置き換える案は不要。このZIPのコードを使用する。

## 再現と修正

本番ビルドとChromium、合成Supabase応答を使って、元コードの管理画面→ライブのタネへの再遷移が10秒以内に完了しない症状を再現した。元コードから共通のloading.jsだけを外した比較版は30回連続で遷移できた。ログは `docs/evidence/performance-before.txt` と `performance-loading-ab.txt`。

共通loading.jsのSuspense境界を廃止し、内部LinkのuseLinkStatusから遷移中表示を出す方式に変更。フルページ再読み込みにはせず、自己分析の状態を保持する。関連する上流報告: https://github.com/vercel/next.js/issues/86151 。上流内部の原因まで同一と断定するものではない。

## その他の修正

- ライブのタネ: ページ全体のrouter.refreshを廃止。認証済み管理者だけが利用できるJSON APIでボードだけ更新。1リクエストずつ、非表示・離脱時は中断、失敗時は間隔を延ばす。最新の足あと1件のみ取得、理由本文を取得しない。100件単位のページング。
- 共通認証: Supabaseクライアントとプロフィール取得を同一Server Componentリクエスト内で共有。他ユーザー・別リクエストにまたがるキャッシュは使用しない。
- DB通信: 応答本文の読み取りも含めて12秒の上限。書き込みを自動再送しない。
- ライブ: マイクの一文確定ごとの全画面更新を削減。自動更新は完了後に次を予約し、積み重ならないよう変更。コメント・文字起こしは各100件単位で新しい順に取得し、過去分へのリンクを追加。
- 知識地図: 全カード・全ユーザータグの転送をDB集計に変更。RLSで読めるデータだけ集計。描画はカードが多い順に最大60タグ。
- タグ辞書: 発言履歴全件の転送をDB集計に変更。タグ取得と集計を並列実行。
- ダッシュボード: AI費用をDBで合計し、1000行で計算が切れる問題も解消。
- カレンダー: 過去の参加ライブ全件を取得せず、表示期間と重なる本人のライブだけ取得。
- 管理者メンバー画面: 使用していなかったユーザータグの取得を削除。エージェント画面も不要な列を削除。
- タネ詳細: 一覧の先頭300件に含まれないIDでも詳細を開けるよう修正し、人名と足あとを並列取得。
- 日付表示: 毎回のロケール文字列生成・再解析を廃止。
- 検索と知識地図内リンク: 通常のクライアント遷移に統一し、先読みは無効化。
- 配信予定作成500: DB関数未適用を判別するエラーを追加。サーバーログはエラーコードのみで、DBの詳細や秘密情報は出さない。

## 検証と限界

`npm test` で既存のエージェント安全性に加え、集計のRLS、非管理者のRPC拒否、1100件の正確な集計、カレンダーの本人・期間制約、ポーリング中断と同時実行防止、タイムアウトを検証する。

ブラウザテスト: `npx playwright install chromium` の後 `npm run test:browser`。テストは本番ビルドを作り、合成DB応答で画面を往復する。実DBの認証を迂回するコードはアプリに追加していない。テスト用ビルドの後に実際に起動する場合は、通常の環境変数で `npm run build` をやり直す。

実DB・実ブラウザ環境での計測値ではない。実データ、ネットワーク、ブラウザ拡張などによる遅延のすべてが解消したとは断定しない。また、プロフィール等の長期的なデータ増加に対する全一覧のページングは今回の変更範囲に含まれない。

検証結果: 本番ビルド成功、単体・DBテスト19件成功。Chromiumで主要画面50回の連続遷移、ボード更新時のRSCリクエスト0件、ライブ履歴ページ送りと自動更新後の遷移・クライアント状態維持を確認。合成データでの結果であり、ユーザー環境の完全再現ではない。
