# タグ「申請」機能: マイグレーション適用と疎通確認

- ブランチ: `ui-requests`
- 症状: プロフィールの「タグにしてほしい」ボタンで
  `Could not find the function public.request_tag(p_on, p_tag_id) in the schema cache`
- 原因: `supabase/migrations/0020_tag_requests.sql` が Supabase に未適用

## 経緯

1. この環境（ローカル）に `supabase` CLI は未インストール・未リンク。
   `npx supabase` は対話なしのインストール承認ができず失敗し、
   `pg` 等の直接 SQL 実行手段もリポジトリ内に無いため、
   この環境から SQL を直接流すことはできなかった。
2. そのため、以下2本を私（ユーザー）が Supabase ダッシュボードの SQL Editor に
   ファイル名の順で貼って実行した。
   1. `supabase/migrations/0020_tag_requests.sql`
   2. `supabase/migrations/0021_ui_demo_seed.sql`
   - 0020 には `drop policy if exists` が1行あり、実行前に中身を確認した。
3. 適用後、Claude 側から読み取り専用の確認を実施（`.env.local` の中身は表示していない）。

## rpc 疎通確認

service_role クライアントから `rpc('request_tag', { p_tag_id, p_on })` を、
未ログイン状態で呼び出した。

```
rpc(p_tag_id=-1, p_on=true) → 申請できるのは、あなたに付いている育ちかけのタグだけです
rpc(p_tag_id=1,  p_on=true) → 申請できるのは、あなたに付いている育ちかけのタグだけです
```

`schema cache` エラーは出なかった（＝関数はスキーマキャッシュ上に見えている）。
`notify pgrst, 'reload schema';` の実行は不要だった。

読み取り専用の追加確認:

```
tag_requests テーブル件数: 3
```

## 補足: 確認表の数値について

依頼メッセージでは 0020 / 0021 それぞれの「確認表の結果」を貼っていただく想定だったが、
実際のメッセージには数値が入っていなかった。上記の rpc 疎通確認と `tag_requests` の件数（3件）で
代わりに裏取りしている。期待値（0020 → 1/1/1、0021 → 6以上/3/5/1以上/3）そのものとの突き合わせは、
SQL Editor 側の実行結果を直接見ていないため未確認。

## 画面での最終確認（ユーザー作業）

早坂 悠人でログイン → プロフィール → 知見タグ → PowerQuery の「タグにしてほしい」を押して
「申請中 ✓」になるか確認してください。
