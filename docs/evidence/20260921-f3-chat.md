# F3: チャットも読む（messages, is_agent=false）

記録日時: 2026-09-21 昼過ぎ

## やったこと

`docs/evidence/samples/f3-chat-test.txt`（文字起こし本文はあえて雑談だけにして、
知見・興味が一切出ないようにした）をライブ#17として開き、
`messages`に2件チャットを直接挿入した（service_roleで。RLSの検証はF5で別途行う）:

- 星野陸: 「実はPower Automateで承認フローを自動化する話に興味があります。」
- 郡司蓮: 「私はプロンプト設計についてかなり詳しいです。良いプロンプトの書き方をいつも工夫しています。」

## 結果（`--dry`→本番）

```
発言 2行 / チャット 2件 / 参加者 2人
...
貼る 2件（✅正式 2） / 落ちた 0件

"cards": [{ "tag": "プロンプト設計", "user_id": "88feab1d-...(郡司蓮)" }]
"interests": [{ "tag": "Power Automate", "user_id": "226578cf-...(星野陸)" }]
badRefs: []
```

本番実行後、DBを確認:

```
knowledge_cards (live_id=17):
  id=28 speaker_id=88feab1d-...(郡司蓮) headline="プロンプト設計の専門知識"

user_tags (星野陸):
  tag_id=2 (Power Automate) kind=interest   ← チャットから正しく付いた
```

文字起こし本文には知見・興味に該当する発言が無いため、これらは**すべてチャット由来**であり、
`speaker_id`/`user_id`もチャットの送信者と完全に一致している。

## 確認できたこと

- `scripts/recorder.mjs`が`messages`（`is_agent=false`のみ）をライブ番号で読み、
  文字起こしの後ろに`[c1]`のような行番号を付けて足す実装が正しく動いている
- 話者は`messages.user_id`から取り、行番号の空間を文字起こし（`s`）とチャット（`c`）で
  分けたことで、話者の取り違えは起きなかった（`badRefs: []`）
- `lib/agents/prompts/recorder.md`を`s12`/`c3`という**文字列**を返す仕様に書き換えたが、
  LLMの出力もこの形式に正しく追従した
