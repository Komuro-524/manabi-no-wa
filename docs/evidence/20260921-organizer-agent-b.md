## ① --dry の結果（要約）

`docs/evidence/samples` は使わず、`0006_demo_seed.sql` で投入したデモ社員10人の
`user_tags`（興味・知見）を材料にした。興味を持つ人がいる6タグだけがLLMに諮られ、
残り38タグ（候補タグの多くや、興味の付いていない議事録の書き方など）は
**コード側で判断すら不要と分かるためLLMを呼ばずにスキップ**された（コスト0円）。

| タグ | 興味人数 | 判断 |
|---|---|---|
| Power Automate | 3人 | wait |
| 生成AI活用 | 5人 | **open** → 早坂悠人に打診まで実行 |
| プロンプト設計 | 2人 | wait |
| データ可視化 | 1人 | skip |
| SQL | 1人 | wait |
| エージェント設計（0002番タスクで official 昇格済み） | 3人 | wait |

費用: $0.0034（6回のjudge + 1回のpick_invitee）

## ② 実書き込み1回目の結果

```
新規open 2 / wait 3 / skip 1
打診 2 / 日程確定 0 / 終了処理 0 / 断念 0
費用 $0.003970
```

- 「生成AI活用」→ **open** → 相談役の候補（コード側で `user_tags.kind='knowledge'` から作成した
  候補リスト1名）から LLM が選定 → 早坂悠人に `invitations` を作成
- 「エージェント設計」→ **open** → 桜庭芽衣に打診
- 「データ可視化」→ **skip**（詳しい人が0人で、そもそも声をかけられる相手がいない）
- 判断理由はすべて `quest_steps.reason` に残っている（`skip`/`wait` を選んだ理由も含む）

## ③ 実書き込み2回目 — 「1タグにつき進行中の企ては1つ」を確認

同じコマンドをもう一度実行した。

```
📋 進行中の企て: 5件

--- 企て#1「Power Automate」status=scouting ---
--- 企て#2「生成AI活用」status=inviting ---
   ⏳ 早坂 悠人 からの返事待ち（0日経過）
--- 企て#3「プロンプト設計」status=scouting ---
--- 企て#5「SQL」status=scouting ---
--- 企て#6「エージェント設計」status=inviting ---
   ⏳ 桜庭 芽衣 からの返事待ち（0日経過）

🔍 新規タグの判断（進行中の企てが無いタグのみ）

--- タグ「データ可視化」（興味1人）---
   → wait: ...
```

### 読み方

- 1回目で `open`/`wait` になった5タグは、**2回目では新規タグ判定ループの対象から自動的に除外**され、
  代わりに「進行中の企てを1件ずつ次の一手へ進める」処理に回った
  （`quests_one_active_per_tag` の部分ユニークインデックスと、コード側の `activeTagIds` 除外の二重防御）。
- `生成AI活用` と `エージェント設計` は `inviting` 状態で、送った直後（0日経過）なので
  **催促も再打診もせず「返事待ち」と表示するだけ**で終わっている
  （3日返事が無ければ次の候補へ回す設計。`docs/QUESTIONS.md` の想定どおり）。
- 1回目で `skip`（`データ可視化`）だったタグは `status='skipped'` で **進行中ではない** ため、
  2回目で再びLLMに諮られ、今回は `wait` という別の結論になった。
  「skipは永久追放ではなく、材料が変われば毎回考え直す」設計が動いていることを示す。

## 停止条件（コードで保証。今回は境界に達していない）

| 条件 | 実装場所 | 今回の状態 |
|---|---|---|
| 前回のライブ終了から14日 | `tags.last_live_at` を見てLLMを呼ぶ前に code だけで skip | 今回のタグはすべて `last_live_at = null`（未開催）なので該当なし |
| 同じ人への打診は週2回まで | `recentInviteCount` で候補リストから事前に除外 | 該当なし（全員0回） |
| 候補3人に断られたらエスカレーション | `quest.tried_count >= 3` で `abandoned` + コンソールに🚨バナー | 未発生（全員まだ返事待ち） |
| 企てが14日動かなければ断念 | 各企ての `created_at` からの経過日数で判定 | 未発生（作成直後） |
| 1周あたりのコスト上限（既定$1.00） | `spent >= BUDGET_USD` でLLM呼び出しをスキップし `wait` に倒す | 未到達（$0.004程度） |

これらはすべて `scripts/organizer.mjs` の中で**LLMの出力を待たずにコードで判定**しており、
LLMがどんな出力をしても停止条件そのものは動かせない。
