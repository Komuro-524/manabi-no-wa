`docs/demo-transcripts/` に「DX推進担当が集まる社内勉強会」という設定で3本作成した。
社名・人名はすべて架空。`supabase/migrations/0006_demo_seed.sql` で投入した架空社員10人を
話者として再利用し、実行すると既存のデモ社員に知見・興味タグが積み増される設計にした。

| ファイル | テーマ | 詳しい人 | 興味を持つ人 |
|---|---|---|---|
| `01-power-automate.txt` | Power Automateの承認フロー自動化 | 綾瀬 大輝 | 星野 陸・神谷 美月・千葉 陽菜 |
| `02-sql.txt` | SQLで集計を速くする | 神谷 美月 | 桜庭 芽衣・藤代 咲良・郡司 蓮 |
| `03-gijiroku.txt` | 議事録の書き方の見直し | 松永 蒼 | 白石 結衣・早坂 悠人・星野 陸 |

いずれも知見カードと興味タグの両方が取れる会話にし、アンコールの発言も混ぜた。

## ⚠️ 途中で起きたミスと、その場での対応（正直に書く）

最初に `01-power-automate.txt` を書いたとき、話者名を **「星野陸」のようにスペース無し**で
書いてしまい、`0006_demo_seed.sql` の社員名 **「星野 陸」（スペース有り）** と文字列が
完全一致しなかった。`scripts/recorder.mjs` は話者名を `display_name` の完全一致で照合するため、
**別人と判断して架空社員4人を重複作成**してしまった（`live #3` とその知見カード2件も実データとして書き込み済み）。

気づいた時点で、CLAUDE.md の絶対ルール「破壊的SQLは実行前に必ず人間に確認する」に従って
**削除は実行していない**（実際、削除しようとしたら Claude Code 側の安全装置にも止められた）。
代わりに:

1. 3本すべての話者名をスペース入りの正しい表記に修正した
2. 詳細と削除候補SQLを `docs/QUESTIONS.md`（「🚨 破壊的操作でDBに残ったゴミデータ」）に記録した
3. 修正後の `02-sql.txt` / `03-gijiroku.txt` を実行し、**今度は重複が発生しないこと**を確認した
4. `01-power-automate.txt` は既に壊れたライブ(`live#3`)があるため、**あえて再実行せず**
   人間の判断（先にゴミを消すか／そのまま追加で流すか）に委ねた

`npm run evidence -- --label demo-transcripts-final` で確認した直近5件の知見カード:

|---|---|---|
| 5 | 議事録の書き方 | 松永 蒼 |

| 3 | SQL | 神谷 美月 |
| 2 | Power Automate | 綾瀬大輝（★スペース無し＝ミスで作られた重複アカウント） |

3・4・5番のカードは正しく既存の社員（スペース有り）に紐づいている。
1・2番だけが、修正前の失敗した実行の名残。

## この失敗から分かること

- `recorder.mjs` の話者照合が**表記ゆれに弱い**（完全一致のみ）ことが実データで明らかになった。
  本番でログイン済み社員から話者を引く設計に変える際は、表記ゆれではなく `user_id` そのもので
  紐づける（＝この問題自体が起きなくなる）はずだが、念のため `docs/QUESTIONS.md` に残した。
- 「破壊的SQLは人間の確認を待つ」というCLAUDE.mdのルールが、実際にミスをリカバリーする場面で
  そのとおりに機能した（安全側に倒す設計の価値を身をもって確認できた）。
