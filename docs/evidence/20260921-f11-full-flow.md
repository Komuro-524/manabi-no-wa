# F11: 打診 → 引き受け → 日程 → 予約 → 最初の一言 を最後まで通す

記録日時: 2026-09-21 昼過ぎ

## 事前準備

- `supabase/migrations/0013_calendar_seed.sql` を適用。架空社員10人に
  「明日（2026-09-22）15:00-16:00」を全員分埋め、3日後・7日後の10:00-11:00にも予定を散らした。
  日本時間で正しく入っているかを確認:

  ```
  開始_日本時間          人数
  2026-09-22 15:00       10
  2026-09-24 10:00       10
  2026-09-28 10:00       10
  ```

- `organizer.mjs`の`pickFreeSlot()`のバグを修正:
  - `from`を「明日0:00（ローカル）」に固定（旧実装は「いまから24時間後」で、
    実行時刻によっては当日の早い時間帯の予定を見落としていた）
  - 予定の絞り込みを`starts_at`の範囲だけでなく「区間の重なり」
    （`starts_at < to and ends_at > from`）に直した

## 通しの実行

### ① 打診（既存データ。事前に打診済みだった quest#2「生成AI活用」→ 早坂悠人）

quest#2は前回のセッションで既に`invitations`が`sent`の状態だった
（`quest_steps`: judge→invite で打診まで完了済み）。

### ② 引き受け（anonキー・実ログインで本人が承諾）

```
node .tmp_f11/accept.mjs
ログイン: 1c92b672-...（早坂悠人）
respond_invitation結果: OK
```

`respond_invitation()`をservice_role経由ではなく、早坂悠人本人としてログインした
anonキーのセッションから呼び出した（RLSのsecurity definer関数が正しく動くことも確認）。

### ③④⑤ organizerを実行 → 日程調整・予約・最初の一言

```
node scripts/organizer.mjs

--- 企て#2「生成AI活用」status=inviting ---
   📋 企て更新 → id=2 {"status":"scheduling","current_invitee":"1c92b672-..."}
   🧾 判断ログ → [invite/open] 早坂 悠人 が快諾。日程調整へ進む
   🎙️ ライブ予約 → 2026-09-23T06:00:00.000Z
   📋 企て更新 → id=2 {"status":"opened","live_id":19,...}
   💬 最初の一言 → "「生成AI活用」の回、早坂 悠人さんに話してもらいます。よろしくお願いします！"
   🧾 判断ログ → [schedule/open] 早坂 悠人 の空き時間から 2026/9/23 15:00:00 に予約し、最初の一言を投稿した（free/busyのみ参照）
```

**予約枠は「明後日（2026-09-23）15:00 日本時間」になった。** 「明日」15:00は
全員の予定で埋まっているため、正しく1日ずれたことが確認できる
（free/busyを見て日程をずらす様子の実演）。

## 確認できたこと

- `quest_steps`が **judge → invite（打診）→ invite（快諾）→ schedule** の順で並んでいる
  （残る`open`はライブが実際に終了した時点で記録される。DESIGN §3.2の手順どおり）
- `lives`に予約済みの1本が作られ、`scheduled_start`が**free/busyの実データを見て
  ずらされた**（明日ではなく明後日）
- `messages`に`is_agent=true`の「最初の一言」が入った
- `respond_invitation()`は本人のanonキーセッションから正しく呼べる（service_role経由ではない）
- `pickFreeSlot()`のバグ（実行時刻依存でクエリ範囲から予定を取りこぼす）を修正し、
  修正後の挙動が意図どおりであることを実データで確認した
