# Named Router 切り替えによる費用比較（orcarouter/auto → orcarouter/manabi-recorder）

記録日時: 2026-09-21 昼

タグ付けエージェントA（`scripts/recorder.mjs`）が使うモデル指定を
`orcarouter/auto`（候補は全モデル）から `orcarouter/manabi-recorder`
（Named Router。フロンティア級には上がらない候補だけで構成）へ切り替えた前後で、
**同じ3本のデモトランスクリプトを同じ内容のまま**再実行し、費用と選ばれたモデルを比較した。

## 比較

| | 合計費用 | 選ばれたモデルの傾向 |
|---|---|---|
| before（auto） | $0.037454 | 都度違う（deepseek系。1回は高価な `-pro` 系にまで上がった） |
| after（manabi-recorder） | $0.000850 | **毎回同じ `openai/gpt-oss-120b`（安定）** |
| 削減率 | **約97.7%削減**（44倍） | ルーターの候補を絞ったことで、たまたま高価なモデルに化けるブレが無くなった |

## 副作用として見つかったこと（正直に書く）

`manabi-recorder`ルーターに切り替えたことで**選ばれるモデルが変わった結果**、
タグの書き方の癖も変わった。今回、3本とも既存の正式タグ名と完全一致せず、
🚪門1で知見カードの多くが「辞書に無い候補」として落ちた:

| ライブ | LLMが書いたタグ | 辞書の正式名 | 結果 |
|---|---|---|---|
| #9 | `PowerAutomate`（スペース無し） | `Power Automate` | 不一致で落ちる |
| #10 | `SQL最適化` / `インデックス` | `SQL` | 不一致で落ちる（`SQL`単体は書かれなかった） |
| #11 | `議事録` | `議事録の書き方` | 不一致で落ちる |

以前の`auto`実行（live#6〜#8）ではタグ名が辞書と一致していたため、
**費用だけを見て「安いモデルの方が良い」と即断するのは危険**という発見でもある。
コストと抽出品質はトレードオフになり得るため、辞書と一致しやすいモデルを
Named Routerの候補に優先的に入れる、あるいは🚪門1に「かな読みが近い正式タグへの
自動吸着」（DESIGN.md §5 門1の検査3で言及されている「空似」判定）を実装するかの
どちらかの対応が要る。`docs/QUESTIONS.md`に記録する。

## その後の整理（2026-09-21 昼・設計に照らして）

上の「副作用」は、**モデルの問題ではなく実装の穴**だった（`docs/QUESTIONS.md` 末尾の回答を参照）。

- `PowerAutomate` は表記ゆれ → 正式タグ `Power Automate` に寄せるよう門1を直した
- `SQL最適化` `インデックス` `議事録` は **正式タグより細かい新しい話題**。設計上は捨てるのではなく
  **候補として辞書に入れ、カードも作る** のが正しい。語る人が増えれば格上げ候補として管理者に届く
- 以前の実装は候補を捨てていたので、「辞書と一致しない＝落ちる」に見えていた

修正後に同じ3本を `--dry` で流した結果は、この下に追記する。

## 【4】修正後、正式タグ一覧を渡したうえでの --dry 結果（live#9〜#11）

その結果、**3ライブとも「↩︎ 表記ゆれ」の吸着は1件も発生しなかった**
（LLMが最初から正式タグの表記どおりに書くようになったため。空似吸着ロジック自体は
`PowerAutomate`のような過去の表記ゆれ候補には別途効いている＝【2】参照）。

## 【6】本番取込（live#12〜#14）後の辞書の状態

`docs/QUESTIONS.md`の回答どおり、事前に以下を実施してから本番取込した:
- `PowerAutomate`（表記ゆれ候補）→ `status='rejected', alias_of=<Power Automateのid>` に更新
- 残る `candidate` 31件の `mention_count` を 0 にリセット（壊れた数え方の後始末）
- live#9〜#11（旧実装で作られたライブ）を削除し、live#12〜#14として再取込

再取込後:

| status | 件数 |
|---|---|
| official | 12 |
| candidate | 36 |
| rejected | 4 |
| banned | 3 |
| **proposed（格上げ候補）** | **0**（新しい候補はまだ延べ1回・話者1人のため、閾値の延べ3回 or 2人に未到達） |

候補タグに付いた知見カード: 今回作られた6件中1件（`インデックス最適化`。他5件は正式タグ）。
これは設計どおりの動き ——**候補の段階からカードもuser_tagsも作る**が、
`official`になるまでは一般には見えず（RLS）、`proposed`（管理者の承認待ち）になるのも
まだ先、という「タグの一生」（DESIGN.md §5.4）の初期段階がそのまま観測できている。
