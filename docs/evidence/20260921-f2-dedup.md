# F2: 同じライブで同じ人は1回と数える（tag_mentions重複排除）

記録日時: 2026-09-21 昼過ぎ

## やったこと

`docs/evidence/samples/f2-dedup-test.txt`（神谷美月が1人でSQL関連の話を3回する短いデモ）を
新規に作り、実際に`open-live.mjs`→`recorder.mjs`で取り込んだ（ライブ#16）。

## 結果

```
knowledge_cards for live 16:
  #25 tag_id=6(SQL)    "ウィンドウ関数で順位付けが簡単に"
  #26 tag_id=6(SQL)    "再帰CTEで階層データを扱う方法"
  #27 tag_id=55(実行計画) "実行計画の確認で遅いクエリを特定"

tag_mentions for live 16:
  tag_id=6(SQL)     user=神谷美月 live=16 knowledge   ← 1行のみ
  tag_id=55(実行計画) user=神谷美月 live=16 knowledge   ← 1行のみ

行数: 2
```

神谷美月は同じライブ内で「SQL」というタグに該当する発言を**2回**（カード#25・#26）しているが、
`tag_mentions`には**1行だけ**記録された。F2修正前は`bump()`が呼ばれるたびに無条件で
`mentionLog`に積んでいたため、この場合3行（SQL×2 + 実行計画×1）になっていたはずである。

## 確認できたこと

- 修正: `scripts/recorder.mjs`の`bump()`に`(tag_id:user_id)`のSetチェックを追加し、
  同じライブ内で同じ人が同じタグを何回語っても`tag_mentions`には1行しか残らないようにした
- これにより「延べ回数」の定義が「発言の回数」ではなく**「何回のライブで語られたか」**に一致する
  （1人が1回のライブで熱心に語っても、それだけで格上げ候補の閾値を満たせなくなる）
- `tags.mention_count`（累計の表示用カウンタ）は従来どおりカード単位で加算する
  （こちらは「表示用の延べ発言数」であり、格上げ判定には使っていないため対象外のまま）
