# タグ昇格の実演（育ちかけタグ → 格上げ候補 → 正式）

記録日時: 2026-09-21 昼

DESIGN.md §5.4「タグの一生」のうち、**候補 → 格上げ候補 → 正式**の一連の流れを、
「別の会で、別の人が、同じ話題を話す」という実データで最初から最後まで通した記録。

## 【1】before — 昇格前の状態

`live#13`（02-sql.txt。神谷美月が「日付列にインデックスを張った」と発言）の取り込みで、
「インデックス最適化」は候補として1件だけ生まれていた。

```
tags: インデックス最適化
  id=53, status=candidate, mention_count=1

tag_mentions (tag_id=53): 1件
  live#13: 神谷 美月 (knowledge)
```

## 【2】4本目の文字起こしを --dry で確認

`docs/demo-transcripts/04-report-speedup.txt`（新規。02に居なかった早坂悠人が
同じ「インデックス」の話をし、千葉陽菜が「教えてほしい」と興味を示す設定）を
`open-live.mjs`で開き（→ライブ#15）、`recorder.mjs --live 15 --dry`で確認した。

**確認したいポイント**: 早坂さんの知見カードのタグが、育ちかけタグ一覧に含まれる
「インデックス最適化」の表記のまま使われるか（別の語に割れないか）。

```
📣 格上げの条件: 直近30日に 延べ3回 または 2人以上
   📣 格上げ候補になる  インデックス最適化  （これまで延べ1回／1人 ＋ 今回1回 → 延べ2回／2人）
   🌱 候補のまま        インデックス        （これまで延べ0回／0人 ＋ 今回1回 → 延べ1回／1人）
   📣 格上げ候補になる  実行計画            （これまで延べ0回／0人 ＋ 今回2回 → 延べ2回／2人）

"cards": [
  {
    "tag": "インデックス最適化",
    "状態": "🌱候補",
    "user_id": "1c92b672-c65a-48c1-8ce3-e2c602793783",   ← 早坂悠人
    "headline": "複合インデックスの列順で性能が大きく変化"
  }
]
```

✅ **想定どおり「インデックス最適化」の表記のまま使われた**（`<growing>`で育ちかけタグを
渡すようにしたefb9aceの修正が効いている）。「インデックス設計」のような別語にはならなかった。

## 【3】本番取込 → 格上げ候補になった

```
node scripts/recorder.mjs --live 15

📣 格上げ候補にした（管理者の承認待ち）:
  インデックス（直近30日で延べ4回／3人）
  インデックス最適化（直近30日で延べ2回／2人）
  実行計画（直近30日で延べ3回／3人）
```

「インデックス最適化」は `candidate → proposed` になった（神谷1人 + 早坂1人 = 2人。
`TAG_PROPOSE_MIN_SPEAKERS`の既定値2人に到達）。

## 【4】管理者の承認

```
node scripts/approve-tag.mjs "インデックス最適化" --dry
  🏷️ 「インデックス最適化」 現在の status: proposed
     🧪 --dry なので official には昇格させません

node scripts/approve-tag.mjs "インデックス最適化" --note "第2回と第4回で別の人が同じ話をしたため"
  🏷️ 「インデックス最適化」 現在の status: proposed
     ✅ official に昇格した（proposed → official）
     メモ: 第2回と第4回で別の人が同じ話をしたため
```

## 【5】after — 承認後の確認と「遡って付く」の証拠

```
tags: インデックス最適化 → status = official ✅

user_tags (tag_id=53):
  id=50  神谷 美月  knowledge  strength=1  updated_at=2026-09-21T02:55:49（live#13取込時のまま）
  id=54  早坂 悠人  knowledge  strength=1  updated_at=2026-09-21T03:46:02（live#15取込時のまま）
```

**この2行は承認の前後で1バイトも書き換えていない。** `tags.id=53`の`status`列を
`proposed → official`に更新した、ただ1行のUPDATEだけで、神谷美月・早坂悠人の
両方に「正式タグとして全員に見える」効果が遡って及んだ（DESIGN.md §5.4の
「正式になった瞬間、過去に語った人全員に遡って付く。バックフィル処理は要らない」を
実データで確認できた）。

### ⚠️ 正直に書く：千葉さんはこのタグを持っていなかった

依頼文では「神谷さん・早坂さん・千葉さんが全員そのまま」を確認するよう指示があったが、
実際に調べたところ、**千葉陽菜さんの興味タグは「インデックス最適化」ではなく
別のタグ「インデックス」（id=49）に付いていた**（LLMが千葉さんの発言を別語で拾ったため）。

```
tags: インデックス（id=49） → status = proposed（まだ承認されていない。別タグなので今回の昇格の対象外）
user_tags (tag_id=49):
  早坂 悠人  knowledge  strength=2
  白石 結衣  interest   strength=1
  千葉 陽菜  interest   strength=1
```

「インデックス」と「インデックス最適化」が今回のデモでは統合されず、別々の候補として
育っている状態。これも育ちかけタグの限界（`<growing>`一覧を見せても、LLMが微妙に
違う語を選ぶことはある）として正直に記録しておく。「遡って付く」の実証自体は
神谷美月・早坂悠人の2人で成立している。
