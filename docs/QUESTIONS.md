# 回答（2026-09-21 昼）— 「Named Router切り替え後、タグの表記ゆれで門1の通過率が落ちた」

**候補A・B・Cのどれでもなく、「タグの流れが会議の決定どおりに実装されていなかった」が原因だった。**

> 会話に出た語は Aが候補として辞書に入れる → 延べ3回 または 2人以上 で「格上げ候補」→ **管理者がOKしたら正式**。
> AIが勝手に格上げするのは危ない。格上げ候補として出すところで止める。

ところが `recorder.mjs` は、辞書に無い語や候補のタグを **「まだ候補」として捨てていた**。
候補の件数（`mention_count`）も増えず、格上げ候補にする処理も無かった。
`auto` 時代は モデルがたまたま正式タグと同じ表記で書いていたので、この穴が見えていなかった。

| LLMが書いた語 | 設計どおりの扱い |
|---|---|
| `PowerAutomate` | **表記ゆれ**。正式タグ `Power Automate` に寄せる（門1 検査3の簡易版として実装） |
| `SQL最適化` `インデックス` | **正式タグより細かい新しい話題**。捨てずに **候補として辞書に入れ、カードも作る**。語る人が増えれば格上げ候補として管理者に届く |
| `議事録` | 同上 |

直したこと（コミット 6ef638c / a1d1a51 / 7052dad）
- 候補・格上げ候補・新語でも知見カードと `user_tags` を作る
- `mention_count` を毎回加算し、延べ3回 または 2人以上 で `proposed` にする（`official` にはしない）
